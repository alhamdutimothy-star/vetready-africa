# Login reliability review

The confirmed defect was a fresh, uncached discovery fetch on every login and callback, each with a five-second timeout. Consequently a successful login/logout never insulated the next login from temporary discovery failure. Logout does not mutate OIDC discovery/configuration or reuse flow state. No session or cookie from a previous attempt is required by the login route.

The owner supplied a sanitized Windows event identifying stage discovery and errorName TimeoutError. This confirms discovery exceeded the application's deadline; it does not establish whether the underlying delay was DNS, proxy, transport or provider response latency. The original login deadline was five seconds while preflight permits ten. Discovery now uses the same ten-second per-attempt deadline as preflight, together with bounded caching and retry. No credential or CSRF failure is indicated by this event. No secret/configuration changes accompany this correction.

The discovery module caches only successfully validated, immutable public metadata for five minutes, keyed by exact issuer and runtime mode. Concurrent requests share one in-flight promise. Memory is bounded to one trust-context slot. Expired metadata is never served during an outage; rejected promises are removed so later requests can recover without restarting. Network timeouts, specified transient transport errors and HTTP 502/503/504 receive at most one retry, with ten seconds per fetch attempt (at most two attempts). Rate limits, authorization errors, TLS failures, invalid documents, issuer mismatches and insecure endpoints are not bypassed or retried. No permanent outage can be made successful by a cache; cold/expired-cache failures still return a safe 503.

Fresh random state, nonce and PKCE values and independently encrypted flow cookies are generated per login. The login route explicitly uses Node.js and dynamic execution, with no-store responses. Configuration is validated on every request rather than retaining configuration secrets in a separate cache. Callback signature/issuer/audience/scope checks and database session ownership/revocation remain unchanged. The same-origin referrer-policy logout fix and strict Origin checks remain in place.

Retain sanitized diagnostics. Internal events distinguish configuration, discovery, flow generation, authorization redirect, flow encryption and cookie setting. Only allowlisted exception names/messages, transport codes and an internally typed numeric discovery HTTP status are logged. Raw errors, causes, stacks, URLs, responses, environment files and per-user flow data are never serialized. Unlisted messages are withheld. The browser always receives the generic failure response.

Local acceptance: apply the incremental patch only after the prior logout and diagnostic patches. Restart Next.js, then complete three login → callback → dashboard → logout cycles without restarting. Check that each login returns 307, callback returns 307, dashboard is authenticated, logout returns 303 and protected navigation requires fresh authentication. Do not share callback URLs, network exports, cookies or tokens. If any login returns 503, capture only the sanitized auth.login.failed event from the web terminal; the underlying latency source requires further investigation if timeouts persist. Synthetic success is not live Windows/Auth0 acceptance.

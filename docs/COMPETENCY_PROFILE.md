# Phase 3G competency profile

Candidates can open `/competencies` and `/skills-passport` from their dashboard or development workspace. Both are private authenticated views. They show source metadata and independent evidence facets, not professional awards. The first five categories are self-declared, document verified, knowledge assessed, case assessed and practically verified. A category heading is not proof of verification: each has its own recorded state. Simulation/workplace evidence remains separately visible.

The profile provides pathway/version filtering, bounded competency pages, per-competency source history and explainable gaps. Learning completion and group-level claims are displayed separately. Passport provenance previews are bounded to five sources per visible competency; the linked owner detail provides paginated history. Aggregation itself has no UI record cap.

`CLAIMED ≠ ASSESSED ≠ VERIFIED`. Training, knowledge and case assessment never confer practical verification. Revoked, superseded, withdrawn, rejected, revision-requested and expired sources remain visible but cannot silently count as effective evidence. Shared competencies retain exact child/source versions and original pathway context; reuse never establishes pathway-specific readiness.

Professional requirements remain UNCONFIGURED / REQUIRES DOMAIN EXPERT VALIDATION. Job Ready, Field Ready, Advanced, certification and licensing determinations remain unavailable. No pass marks, weights, validity periods, gates or assessor professional-authority rules are supplied.

An explicit save creates a private immutable historical receipt containing normalized metadata, engine version, evaluation time and SHA-256 digests. It does not freeze current competency status. Every current view recalculates from authoritative records; historical reads replay and verify the saved engine. Snapshots have no sharing feature.

Migration 015 is additive and forward-only. Apply it through the normal migration process after reviewing the unstaged changes. This implementation's tests apply it only in the dedicated isolated local test database. Authentication, private configuration and migrations 001–014 are preserved.
